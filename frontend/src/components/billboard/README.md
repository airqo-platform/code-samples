# Live billboard

Open `/billboard` to choose a country or enter a cohort ID, then open or copy the generated display link. Country changes reset the grid and search. Membership uses country metadata and monitoring-site membership rather than hardcoded place names. A home-page action links to the builder. Displays use named locations rather than averaging unrelated monitors. Locations rotate every 15 seconds by default. Users can pause or resume, including inside fullscreen. Selecting a location manually pauses rotation. Reduced-motion preferences stop illustration animations.

The server uses `API_TOKEN` and the same upstream forecast API as the existing site. Forecasts and their weather fields require AirQo Premium access. Missing forecast data does not prevent available readings from appearing. The display refreshes every 60 minutes and upstream responses are cached for an hour. Measurement timestamps remain visible without age warnings; previously loaded data remains visible with a warning if refresh fails.

Any valid cohort ID can be entered directly, with no local allowlist. AirQo still applies the server token's permissions. A cohort ID is an identifier, not a password: this display publishes the data the server account can retrieve for that cohort. No credentials appear in copied links or embeds.

The display supports fullscreen and iframe embedding. Dates and times use the viewer's browser timezone. Daily forecast weather stays tied to the selected location and day. The display shows the weekly forecast only, with no hourly forecast control.

The theme selector offers Navy, Light and Forest. The choice is remembered locally and included in copied links and embeds. Fullscreen targets only the Air Quality Live panel, including its weekly forecast and weather; surrounding page controls stay outside fullscreen. Exit with Escape or the panel's Exit fullscreen button.

The country selector shows small country flags. Locations whose latest reading has no valid PM2.5 value are excluded from display and rotation; forecast days with missing PM2.5 are omitted. Zero is a valid reading. The selected day's dated forecast recommendation appears directly after the current health tip, before the measurement timestamp.

If native fullscreen is unavailable, the same button opens a viewport-filling presentation mode. Both modes keep the QR and AirQo credit in the footer, separate from the scrollable readings and forecast area.

The panel includes a locally generated SVG QR code labelled **Scan to view this air quality**, also visible in fullscreen. Its destination contains only the current grid or cohort ID, so rotation and appearance changes never change the code. The setup page can download this QR as SVG. Localhost/private-IP previews encode `https://ai.airqo.net/billboard` so phones get a public destination; the feature must be deployed there before those preview codes can be used. Public deployments use their own origin. QR codes use a white background, black modules and a four-module quiet zone in every theme. In fullscreen the header and footer remain visible while the main content scrolls if necessary. The QR and Powered by AirQo credit remain visible at every screen width.

The navy display uses compact WebP copies of the same category faces as the map (35,328 bytes including the unavailable face), native weather emoji, and a small CSS halo animation with reduced-motion support. It adds no map SDK, video, animation library, external image service or font. The API sends the latest reading per site instead of seven days of history, and only the forecast fields used by the UI. Default JSON responses are capped at 1,000,000 bytes to reserve space for shared assets within the 2 MB target; oversized scopes return a message asking for a smaller scope. Shared framework assets and deployment analytics must also be included when measuring total browser transfer.

Current-condition guidance is category-based; daily advisory text uses the API when supplied. Health guidance should receive editorial review before public launch.

Run `node --test src/lib/billboard.test.cjs` for normalization, access-control, pagination and partial-failure checks.

Local production measurement with the Lagos grid (33 locations): 1,743 bytes HTML + 366,096 bytes shared static assets + 82,180 bytes data + 235,492 bytes for all six faces = 685,511 bytes transferred with gzip requested. This conservatively includes unused category faces; it excludes third-party analytics/extensions. Sizes vary with the scope and build.


The Illustration selector offers Category faces or Activity scenes. Activity scenes are inline animated SVGs, with a preferred good-air activity of running, football or yoga. Moderate air uses gentle walking; higher categories use indoor yoga, reading, rest or window-closing scenes. The selected visual and good-air preference travel in shared links. These illustrations are contextual cues, not personalised exercise advice.

The third option, **Realistic animations**, uses thirty eight-frame action strips: five actual activity sequences per AQI category, 240 frames total. The person changes limb, hand and prop poses (walking steps, page turns, typing, drinking, etc.) instead of bobbing a still cutout. Scenes shuffle every nine seconds without repeating within a bag or immediately across bags. The category is always chosen from the current location's PM2.5. Pause animations stops both scene changes and frame playback; reduced-motion preferences use static posters. The UI is dynamically imported only when selected, and preloads only the next action. Action artwork totals 1.75 MB for all thirty sequences, with individual strips around 37-117 KB. Prompts and review GIFs are in `frontend/artwork/billboard/`. The `/billboard` setup card always shows the realistic woman checking her phone, regardless of the display illustration selection.

Credential handling: server callers and persistent cache keys use clean URLs. `fetchAirQo` adds AirQo-required query credentials only inside Node HTTPS request options, bypassing Next fetch instrumentation. Raw upstream errors are discarded, reflected tokens are redacted from response bodies, and cross-origin upstreams/redirects are rejected. The token therefore never enters a logged `URLSearchParams` object. AirQo itself still receives its required query token over HTTPS. Rotate any token that has already appeared in terminal output or shared logs.

Action playback uses CSS sprite steps with no canvas, animation loop, or animation library, avoiding ghosted outlines from overlapping poses. Continuous strides/pedalling loop forward; gestures play forward and back to avoid abrupt resets. Scene changes use a brief 120ms entrance fade with no fade-out. True high-frame-rate character animation requires richer source artwork.

Optional activity scenes, the country/grid picker and QR component load in separate chunks when rendered. The global data warmup dynamically imports map/report services only on routes that use them. Grid filtering, weekly forecast selection and timezone suggestions avoid repeating work on unrelated UI updates.
